# hxyfront-62013 木构拆卸归安交接台

在原「木结构榫卯构件测绘」骨架上改造的落架修缮交接前端：管理构件建档、承托关系、临时支撑与「拆卸 → 处置 → 归安 → 校正 → 闭环」全过程交接单。

## 业务规则

- **构件唯一**：构件按「建筑 + 编号」唯一建档；不同建筑允许同编号。
- **拆卸前置支撑**：拆卸前若仍有在原位的下游构件引用（承托关系），必须逐笔先登记临时支撑；否则整次拆卸操作拒绝，且不产生任何落库记录。下游构件已拆卸离场则无需支撑。
- **交接唯一 + 幂等/并发去重**：每件构件同一时间只能有一笔未关闭交接；重复提交直接沿用首次结果，并发提交复用在途的首次 Promise（仅一笔落库，回执标记「沿用首次结果」）。
- **危急构件只能更换**：`危急` 构件不允许原位修补；替换件木材与截面必须与原构件一致（木材做空格/大小写归一，截面兼容 `180×240 / 180x240` 写法）。
- **归安校正闭环**：归安方向与原方向不符时退回「待校正」；校正确认方向仍不符则继续退回，一致后方可进入闭环；闭环时同步拆除该交接单挂接的临时支撑，构件恢复在役。
- **状态一致**：全部状态写入 `localStorage`，刷新页面后关系清单、筛选结果、统计数字与交接阶段保持同一快照。

## 页面结构

- 顶部指标：构件总数 / 未关闭交接 / 拆卸离场 / 待校正 / 危急构件 / 有效支撑
- 侧栏：按建筑、榫卯类型、在场状态、危急程度、关键字筛选；临时支撑登记台
- 构件清单：状态徽标、缺支撑提示、拆卸申请弹窗（下游引用逐笔核对）
- 交接台账：步骤条、原构件档案、支撑快照、分阶段操作与操作日志、已闭环归档
- 关系清单：按建筑维护有向承托关系（防重复、防反向、防环），按构件汇总上下游引用

## 技术栈

React 19 + Vite + TypeScript，状态层为自研订阅式 store（`src/store.ts`），无额外运行时依赖。
